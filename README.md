## Повторный запуск на Windows

Нужен Python 3.12. Сервер RustFS должен быть доступен по `http://127.0.0.1:9000`; объект — `s3://hh-lake/raw/it_vacancies_2024.csv` из работы 3. Java и ZooKeeper устанавливаются локально в эту папку, настройки ОС не меняются.

```powershell
py -3.12 -m venv .venv
.\Run-Lab.ps1 setup
$env:RUSTFS_ACCESS_KEY='ваш ключ'
$env:RUSTFS_SECRET_KEY='ваш секрет'
.\Run-Lab.ps1 start
.\Run-Lab.ps1 quorum
.\Run-Lab.ps1 unsafe
.\Run-Lab.ps1 fenced
.\Run-Lab.ps1 verify
.\Run-Lab.ps1 test
.\Run-Lab.ps1 stop
```

Адрес S3 можно изменить через `RUSTFS_ENDPOINT_URL`. При запуске рядом с предыдущими работами ключи также читаются из локального `../lab/.credentials.json`; файл с ключами в репозиторий не входит.

Каждая копия запускается штатным `bin\zkServer.cmd` из своей папки `servers/zkN`. В конфигурациях отдельные dataDir и myid, клиентские порты 2181–2183, порты кворума 2888–2890, выборов 3888–3890, AdminServer 8081–8083. Все порты слушают localhost.

## Как устроен координатор

- `src/pairs.py`: фильтр вакансий и map/reduce пар из работы 3. В названии есть 1С/1C и слово программист/разработчик/developer/programmer; роль строго «Программист, разработчик». Битрикс/Bitrix и Java Developer исключены. Навыки разделяются по `;`, очищаются, приводятся к нижнему регистру и убираются повторы внутри вакансии.
- `src/coordinator.py`: Kazoo Lock на эфемерных последовательных узлах, сессия 10 секунд; отдельная монотонная эпоха. Через каждые 10 000 строк сохраняются счётчики, идентификаторы и позиция CSV в S3. В ZooKeeper хранится только ссылка на чекпоинт и его SHA-256. Запасной загружает счётчики и пропускает уже учтённый префикс CSV, не пересчитывая пары этого префикса.
- `FENCING` управляет проверкой при публикации итогового указателя. С защитой получатель выполняет одну транзакцию ZooKeeper: `check(epoch, version=token)` и `set_data(result, pointer)`. Объекты CSV в S3 имеют отдельные имена по эпохе. Единственным опубликованным результатом считается тот, на который ссылается `/result`.
- `scripts/run_failover.py`: определяет PID вычисляющего процесса по его журналу, приостанавливает его средствами ОС и проверяет отсутствие событий A в течение паузы. Возобновляет A после завершения B и не ранее 40 секунд. Время смены лидера берётся по общим монотонным часам Windows.
- Задержка 30 мс на пакет из 1000 строк нужна, чтобы успеть приостановить процесс посреди расчёта; это не измерение производительности алгоритма.
- `tests/test_fencing.py` проверяет реальную устаревшую запись до публикации B и после неё. В обоих случаях ZooKeeper возвращает BadVersionError, значение B сохраняется.

В этом опыте старый координатор намеренно продолжает свою вычислительную функцию после потери сессии, чтобы показать действие fencing. Выборы и получателя записи нельзя считать одним механизмом: новая эпоха не останавливает чужой процесс автоматически.

## Файлы

- `servers/zk*/conf/zoo.cfg`, `servers/zk*/data/myid` — конфигурации трёх копий.
- `logs/` — журналы координаторов и stdout серверов. Два зачётных запуска перечислены в `evidence/experiments.json`; предварительные прогоны сохранены в `logs/development/`.
- `evidence/` — выводы команд, полные сессии zkCli, числовые результаты и исходные скриншоты.
- `results/` — четыре результата и эталон работы 3.
- `scripts/evidence_console.py` — локальная страница для чтения настоящих выводов команд. Скриншоты консоли сняты в браузере, это не изображение PowerShell. Запуск: `.\Run-Lab.ps1 console`, адрес `http://127.0.0.1:8766/roles`.

## Почему три сервера

Кворум — большинство: `floor(N/2)+1`. Для двух серверов нужны оба, поэтому потеря одного останавливает запись. Для трёх нужны два, один может отказать. Для четырёх нужны три: четвёртый сервер увеличит расходы, но по-прежнему можно потерять только один. Чтобы пережить два отказа, нужны пять участников. Здесь это три процесса на одном компьютере, поэтому от отказа самого компьютера такой стенд не защищает.

## Почему эпоху проверяет получатель

После истечения сессии ZooKeeper выбирает нового лидера, но старый процесс может просто проснуться после паузы и продолжить запись. Поэтому получатель должен отвергнуть его старый номер эпохи. В этой реализации получатель хранит указатель в ZooKeeper и явно использует его проверку версии в атомарной транзакции. Если писать напрямую в базу или S3, эти записи сами по себе ZooKeeper не проверит: защита должна быть встроена в соответствующий путь публикации.
